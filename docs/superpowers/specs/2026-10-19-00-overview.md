# Recipe Shopping List — Product Overview

**Date:** 2026-10-19
**Status:** Approved design, pending spec review

## Vision

A desktop app that turns a set of chosen recipes into one clean shopping list.
Recipes are imported from CSV into local storage; nothing is cloud-based. The
user picks recipes, sets how many servings they want of each, and gets a
combined list with quantities merged and expressed in sensible units.

## Product decisions (apply to every PRD)

| Decision | Choice |
|---|---|
| Platform | Desktop, cross-platform (developed on macOS) |
| Language / UI | Python 3.11+, PySide6 (Qt) |
| Storage | SQLite via the standard-library `sqlite3`, one file in the OS app-data folder |
| Recipe input | CSV / pasted spreadsheet rows (PRD 1); in-app form later (PRD 5) |
| Quantities | Exact `fractions.Fraction`, never floats |
| Ingredient matching | Normalize case/whitespace/plural only. A more specific name is a different item to buy ("yellow onion" ≠ "onion"). No aliases, no fuzzy matching. |
| List usage | In-app checkboxes + copy unchecked items as plain text |
| Units | US customary and metric, user-chosen output system; volume and mass never inter-convert |

## Architecture

Pure-Python core with a thin Qt shell. All logic lives in `core/` (no Qt
imports) so it is testable with plain `pytest`; `storage/` is the only code
that touches SQLite; `ui/` widgets call into `core`/`storage` and hold no
business logic.

```
shopping_list/
  core/
    models.py      # Recipe, Ingredient dataclasses
    quantity.py    # parse "1 1/2", "½", "0.5" → Fraction; format for display
    units.py       # aliases → canonical unit; conversion & clean-step tables (PRD 4)
    names.py       # ingredient name normalization (PRD 2)
    validation.py  # row/recipe validation rules shared by import (PRD 1) and editor (PRD 5)
    importer.py    # CSV / pasted text → ImportPreview
    shopping.py    # aggregation (PRD 2), scaling (PRD 3), merging by dimension (PRD 4)
    reduce.py      # clean single-unit reduction & US/metric conversion (PRD 4)
  storage/
    db.py          # connection, schema, migrations (PRAGMA user_version)
    recipes.py     # RecipeRepository
    settings.py    # SettingsRepository (PRD 4)
  ui/
    main_window.py
    library_view.py
    import_dialog.py
    recipe_table_editor.py   # reusable editable ingredient table (PRD 1, reused in PRD 5)
    shopping_view.py         # PRD 2
    preferences_dialog.py    # PRD 4
    recipe_editor_dialog.py  # PRD 5
  __main__.py      # `python -m shopping_list`
tests/             # mirrors core/ and storage/; thin pytest-qt smoke tests for ui/
```

### Data model (initial, PRD 1)

```
recipes      (id INTEGER PK, name TEXT NOT NULL, servings INTEGER NOT NULL CHECK (servings > 0),
              created_at TEXT NOT NULL)
ingredients  (id INTEGER PK, recipe_id INTEGER NOT NULL REFERENCES recipes(id) ON DELETE CASCADE,
              position INTEGER NOT NULL, name TEXT NOT NULL,
              quantity TEXT NULL,   -- Fraction as "n/d" or "n"; NULL = "to taste"
              unit TEXT NULL)       -- canonical unit, raw text if unknown; NULL = counted item
```

`recipes.name` is not unique (duplicate import allows "keep both"). PRD 4 adds
`settings (key TEXT PK, value TEXT)`. Schema changes are applied as numbered
migrations keyed on `PRAGMA user_version`.

Database location: `QStandardPaths.AppDataLocation` / `recipes.db`
(macOS: `~/Library/Application Support/<app>/recipes.db`).

## Cross-cutting requirements

- **Errors:** DB open failure shows a dialog including the DB path and exits
  cleanly. Failed writes roll back and show the reason. Import problems are
  always surfaced in the preview, never as uncaught exceptions.
- **Testing:** table-driven `pytest` for all `core` modules; storage tests on
  in-memory SQLite; one `pytest-qt` smoke test per screen.
- **Running:** `python -m shopping_list`.

## Out of scope (all PRDs)

Packaging into a `.app`/installer, printing, `.txt` export, store-aisle
grouping, URL or free-text recipe import, ingredient aliases, fuzzy matching,
volume↔weight conversion, cloud sync, multiple users.
